🔒 Mecanismos de Aislamiento — Garantía de Independencia

1. ThreadPoolExecutor

Cada agente/collector corre en su propio hilo del sistema operativo. Si un hilo se cuelga, no afecta a los demás.

Usado en: _collect_all(), check_services(), collect_agent_status(), dispatch_multi()

2. as_completed()

Procesa resultados conforme llegan, no en orden de envío. El más rápido se procesa primero. Timeout global corta a los lentos sin esperar.

Usado en: _collect_all(), check_services(), collect_agent_status()

3. executor.shutdown(wait=False)

Después del timeout, el executor se apaga sin esperar a los hilos que no terminaron. No hay bloqueo post-timeout.

Usado en: Todos los executor (finally block)

4. Defaults pre-poblados

Cada collector tiene un valor por defecto. Si falla o timeout, se usa el default. El sistema nunca devuelve error por un collector caído.

Ejemplo: GPU → {"available": False}

5. Timeouts individuales

Cada operación tiene su propio timeout: HTTP 2s, WSL subprocess 3s, model query 1s. Timeouts cortos evitan que un servicio lento arrastre a los demás.

Rango: 1s (Ollama models) → 6s (global)

6. Soft imports + try/except

Módulos como monitor_sistema, system_logger, task_dispatcher se importan con try/except. Si uno falta, el sistema sigue con funcionalidad reducida.

Flags: _MONITOR_OK, _LOG_OK, _HEALTH_CHECK_OK
